# Chinese and English Product Specification

## Language behavior

- On first visit, choose `zh-Hans` when the browser prefers Chinese; otherwise choose `en`.
- A visible `中文 / EN` control switches language without losing page state.
- Persist the explicit choice locally and restore it on later visits.
- Navigation, labels, buttons, validation, errors, empty states, dialogs, statuses, analysis labels,
  accessibility names, and Copilot system copy require both languages.
- Company names, job titles, JD evidence, CV evidence, URLs, and recognized technical terms retain
  their source language unless the user explicitly asks for translation.
- AI explanations and Copilot answers follow the active UI language; citations retain source text.
- Dates, numbers, and relative time use the active locale; stored values remain locale-neutral.

## Implementation contract

- Product code uses stable translation keys; user-facing literals do not live in business logic.
- Chinese and English catalogs contain the same key set.
- Missing keys fail CI and test builds. Production logs the key and falls back to English.
- Interpolation parameters are named and validated; translated copy cannot alter record IDs or
  deterministic scores.
- Changing UI language does not trigger reanalysis, change a score, or create a workflow run.

## AI bilingual parity

For the same saved record and scoring version, Chinese and English must return the same score,
recommendation class, cited evidence IDs, proposed action type, and action parameters. Natural
language wording may differ. Bilingual parity is measured by `evals.md`, not subjective screenshot
comparison alone.
